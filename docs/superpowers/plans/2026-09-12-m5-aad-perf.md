# M5 — AAD・性能 実装計画

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** テープ式の随伴自動微分（AAD）で Black–Scholes の全 Greeks を逆伝播 1 回で得て、解析解・バンプと比較するシーン。全シーン共通のパフォーマンスパネル（step 時間ヒストグラム、フレーム時間、dropped、リング占有率）。`perf` を使う計測ワークフローの文書化とベンチの CI 収集。

**Architecture:** AAD は `core/aad/tape.hpp`（`Tape` + `Var`、演算子オーバーロード、2 親までのノード配列、`reserve` 後は割り当てなし）。BS on AAD は **既存の 1 カーネル `bs_price_block<Ops>` に `AadOps` を与える**（M1 で算術を 1 本に集約した恩恵。Δ が解析解と 1e-12 で一致するのは同じ演算列だから）。パフォーマンス計測は `Runner` が step 時間の固定ビン・ヒストグラム（atomic、relaxed）を持ち（RUNNER-11）、描画側の `viz/perf.hpp`（vizcore）が分位・ヒストグラム表示用の純関数を提供する。

**規約:** `CLAUDE.md` と M1〜M4 の約束。

## 型契約

### Task 1 — テープ AAD（`namespace quantviz::core::aad`）

```cpp
class Tape {   // ノード: 値は持たない（Var が持つ）。各ノードは親 ≤ 2 の (index, partial)
public:
    void reserve(std::size_t n_nodes);           // ここでだけ割り当て（AAD-08）
    void rewind() noexcept;                      // 長さ 0（容量は保持）
    std::size_t size() const noexcept;           // = 記録した演算回数 + 入力変数の数（AAD-06 は演算回数で検査 — 入力の分は文書化）
    std::size_t capacity() const noexcept;
    /// 逆伝播: result の随伴を 1 として全ノードの随伴を計算（AAD-04）。adjoints は size() 要素
    void propagate(std::size_t result_node, std::span<double> adjoints) const noexcept;
    // 記録 API（Var が使う）: push_leaf(), push_unary(parent, partial), push_binary(p1, d1, p2, d2) → node index。
    // 容量超過は「記録失敗」を返し、Var は値の計算だけ続ける（NaN や UB にしない。文書化）
};
class Var {   // 値 + ノード index + テープ参照（テープはスコープ内で明示的に渡す: `Tape& t`。thread_local のグローバルは使わない）
public:
    Var(Tape& t, double v);                      // 入力（leaf）
    double value() const noexcept;  std::size_t node() const noexcept;
    friend Var operator+(Var, Var); − × ÷ とスカラとの混合; exp, log, sqrt, norm_cdf(Var)（微分は pdf）, erfc(Var), fma 相当は不要
};
```
AAD-01..08 は `03_tdd_spec.md` の通り。AAD-07: ランダム式（seed 固定、演算を 20 個ランダム合成）で中心差分（h = 1e-6 × スケール）と相対 1e-8。

### Task 2 — BS on AAD

`AadOps`（`black_scholes.hpp` の Ops 契約: `V = Var`, `splat/add/mul/div/neg/log/erfc/madd/nmsub/msub`、`madd(a,b,c) = a*b + c` として実装）。`BsGreeksAad bs_greeks_aad(Tape&, double S, double K, double T, double r, double sigma, OptionType)` → price, delta, vega, rho, theta（= −∂V/∂T）を 1 回の `propagate` で。AAD-09 Δ = 解析 Δ（1e-12）、AAD-10 ν ρ Θ、AAD-11 = バンプ（相対 1e-6）、AAD-12 = BENCH-06（全 Greeks ≤ 価格計算の 5 倍）。

### Task 3 — Runner 計測と perf 純関数

```cpp
// bridge/runner.hpp（追加）
struct StepHistogram {   // 対数ビン: 100 ns〜1 s を 32 ビン。計算スレッドが relaxed に加算、描画スレッドが読む
    std::array<std::atomic<std::uint64_t>, 32> bins; std::atomic<std::uint64_t> count, total_ns, max_ns;
    static std::size_t bin_of(std::uint64_t ns) noexcept;  static std::uint64_t bin_lower_ns(std::size_t) noexcept;
};
// Runner: tick() の各 step を steady_clock で計測して StepHistogram に記録（`RunnerConfig::measure_every = k` が唯一のスイッチ: 既定 16、0 で計測コードを生成しない。1 step ≈ 20 ns の Streaming では clock 読み（≈ 25 ns）が支配的になるので、k ステップまとめて 1 サンプルにする）。`const StepHistogram& step_histogram() const`。【実装後の注記】計画にあった `measure_steps` フラグは `measure_every = 0` に吸収した。
// viz/perf.hpp（vizcore）
template <std::size_t N> struct FixedHistogram { std::array<double, N+1> edges; std::array<std::uint64_t, N> counts; void add(double v) noexcept; /* 境界は [lo, hi) 、最後は閉 */ };
double percentile_sorted(std::span<const double> sorted, double p) noexcept;   // 線形補間、p∈[0,1]
class Ema { public: explicit Ema(double alpha); void add(double) noexcept; double value() const noexcept; };
double dropped_ratio(std::uint64_t dropped, std::uint64_t received) noexcept;  // dropped / (dropped + received)、0/0 = 0
```
RUNNER-11（`[runner][unit]`）: `tick()` で n ステップ回すと `step_histogram().count == n`（measure_every=1）、`total_ns > 0`、ビンの合計 = count。非計測設定ではサイズ・挙動が変わらないこと。PERF-01..04 は仕様通り。

### Task 4 — AAD シーン

`AadModel`: S は GBM、毎ステップ 3 手法で Greeks（AAD: 1 propagate、バンプ: 4 回の再評価、解析: `bs_greeks`）と各計算時間（`steady_clock`、ns）とテープ長を Snapshot に載せる。`Snapshot{ t, spot, K, T, r, sigma, aad{price,delta,vega,rho,theta}, bump{...}, analytic{...}, ns_aad, ns_bump, ns_analytic, tape_size, seq }`（≤ 256 B）。`Param{ kStrike=1, kSigma=2, kRate=3, kMaturity=4 }`。パネル: 「Greeks (3 methods)」テーブル、「Timing」バー（AAD / bump / analytic の ns、EMA）、「Delta history」（3 本の History が重なることを見せる）、「Control」。AADSCENE-01..03。

### Task 5 — パフォーマンスパネル

`Scene` に `virtual PerfSample perf_sample() const = 0;`（`RunnerScene` が Runner の dropped / queued / capacity / total_steps / step ヒストグラムのスナップショットを返す）。`viz/src/panels/perf_panel.hpp`: `PerfPanel::draw(const Scene*)` — フレーム時間ヒストグラム（`ImGui::GetIO().DeltaTime` を `FixedHistogram<32>` へ、p50/p95/p99）、step 時間ヒストグラム（対数ビンのバー）、dropped 比率、リング占有率。`main.cpp` がメニューバーの "View ▸ Performance" トグルで表示。

### Task 6 — 統合と計測ワークフロー

`docs/04_perf.md`: `perf stat -e cycles,instructions,cache-misses ./build/tests/quantviz_tests "[!benchmark]"`、`perf record -g` → `perf report` の手順、WSL2 での注意（`perf` はカーネルバージョン依存 — 使えなければ `valgrind --tool=callgrind` の代替を記す）、ビフォーアフターの記録表（例: SurfaceMesh の法線更新で reciprocal spacing をキャッシュする最適化を 1 つ実施し、BENCH-04 の前後を記録する）。CI: `bench` ジョブ（ubuntu, Release）で `[!benchmark]` を実行し、出力を artifact に保存（情報のみ、ゲートしない）。
